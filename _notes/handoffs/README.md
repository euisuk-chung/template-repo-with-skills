# 작업·리뷰 지침서

`handoff` 스킬이 새로운 세션이나 담당자에게 전달할 작업 요청·리뷰 요청을 작성합니다.
수신자는 이전 대화나 메모리 없이 이 문서와 명시된 저장소·자료만으로 일을 시작할 수
있어야 합니다. 작업 목표, 필요한 배경, 실행 순서와 완료 기준을 문서 안에 담습니다.

## 수신 대상

- [to_codex](to_codex/README.md): 새 Codex 세션에 전달할 지침서
- [to_claude](to_claude/README.md): 새 Claude 세션에 전달할 지침서
- [to_human](to_human/README.md): 개발자·리뷰어 등 사람에게 전달할 지침서

폴더는 작성자가 아닌 **받는 대상**을 뜻합니다. 예를 들어 Codex가 작성해도 Claude에
리뷰를 요청할 문서는 `to_claude/`에 저장합니다. 대상이 불명확하면 먼저 확인합니다.

## 담는 내용

- 수신 대상, 요청 유형(구현·리뷰·조사 등), 목표와 기대 결과물
- 핵심 배경·결정, 작업 범위와 범위 밖 항목
- 저장소·입력 자료의 위치, 작업 또는 리뷰 기준점, 필요한 환경과 접근 권한
- 현재 작업 상태와 변경 파일, 확인된 브랜치·커밋 정보
- 실행한 검사와 결과, 완료한 작업과 진행 중인 작업
- 이번 세션의 결정과 관련 문서 링크
- 실패한 접근, 미검증 가정, 막힌 이유
- 실행 순서, 검증 방법, 결과물 형식과 완료 기준

리뷰 요청에는 검토할 diff·커밋 범위·파일과 검토 관점, 수정 여부, 발견 사항의 보고
형식을 명시합니다. 미커밋 변경을 다른 환경으로 전달할 경우 수신자가 해당 자료에
접근할 수 있는지도 기록합니다. 중요한 지침을 과거 대화나 링크로만 대신하지 않습니다.

## 작성 규칙

파일명은 [공통 파일명 규칙](../README.md#파일명-규칙)에 따라
`<yymmdd-hhmm>-<topic-slug>.md`로 짓습니다. 예: `to_codex/260908-1500-search-filter.md`.
접두어는 생성 시각이며 갱신 시 유지합니다. 같은 주제의 인터뷰 기록이 있으면
주제 슬러그를 사용하되 생성 시각은 각 문서에서 실제로 확인합니다.

같은 수신 대상·요청의 문서가 있으면 먼저 읽고 갱신합니다. 별개 리뷰 요청은
`260908-1600-search-filter-review.md`처럼 목적을 구분하고 구현 지침서를 덮어쓰지 않습니다.
수신 대상별 문서를 여러 개 만들 때도 각 문서만으로 실행 가능하게 작성합니다.
다음 세션에 도움이 되는 실패
기록과 이유는 보존합니다. 확인한 사실과 추론·미검증 항목을 구분하고, 로컬 검사 결과를
배포 환경의 성공으로 기록하지 않습니다.

상세 절차와 문서 형식은 [handoff 스킬](../../.agents/skills/handoff/SKILL.md)을
따릅니다. 요구사항·설계 결정은 [grills](../grills/README.md)의 해당 문서를 링크하되,
요청 이해에 필수인 내용은 지침서 안에도 요약합니다.
